# quiz-me: 질문 은행으로 면접 연습

개발자가 명시적으로 부른 복습이다. "검증 단계에서 예측 퀴즈 금지" 메모리는 작업 중 확인 단계에 대한 것이라 여기엔 해당하지 않는다.

## 1. 질문 고르기

인자를 해석한다 (여러 개 섞여도 된다).

| 인자 | 고르는 법 |
| --- | --- |
| 주제 (예: `concurrency`) | 그 주제 파일에서만 |
| `random` | 전체에서 무작위 |
| `weak` | `_history.md`에서 최근 결과가 × 또는 △인 질문 우선 |
| 숫자 | 그만큼 묻는다 (기본 5) |
| ID (예: `CC-013`) | 그 질문 하나 |
| 없음 | 전체에서 5개: 한 번도 안 물은 것 → 최근 ×·△ → 오래전에 물은 것 순으로 섞는다 |

- `docs/learning/question-bank/_history.md`를 읽어 언제 무엇을 물었고 결과가 어땠는지 본다
- 같은 세션에서 같은 질문을 두 번 내지 않는다. 난이도는 ★부터 섞어 올라간다

## 2. 묻기 (한 번에 하나)

- 질문만 보여 준다: `[3/5] CC-013 · 상황 적용 · ★★` + 질문 본문. **답 핵심은 보여 주지 않는다**
- 개발자의 답을 기다린다. 개발자가 "힌트"라고 하면 답을 주지 말고 방향만 한 줄 준다 (예: "WHERE 절이 하는 일을 떠올려 보세요"). "모르겠다"·"패스"면 바로 4번으로
- 면접관처럼 담백하게. 정답을 유도하는 말투를 쓰지 않는다

## 3. 꼬리 질문 (선택, 한 번)

- 답이 대체로 맞으면 그 답에서 파고들 꼬리 질문을 **하나** 던진다 (답 핵심의 "꼬리 대비"나 실제 면접에서 이어질 질문)
- 답이 많이 비면 꼬리 질문 없이 4번으로

## 4. 채점과 피드백

- 결과: ○(핵심을 다 말함) / △(일부 빠짐·부정확) / ×(틀림·모름)
- 피드백 순서: 잘 말한 것 → 빠진 핵심 키워드 → 틀린 부분 정정 → 그다음에 답 핵심 전체와 📎 링크
- 개발자 답이 은행의 답보다 낫거나 은행 답에 틀린 데가 있으면 솔직히 말하고, 은행의 답을 고친다
- 면접에서 이렇게 말하면 좋다는 30초 답변 한 줄을 덧붙인다 (✍️ 30초 답)

## 5. 기록

질문마다 `docs/learning/question-bank/_history.md` 표에 한 줄 추가:

```markdown
| 2026-12-20 | CC-013 | △ | 처리량 상한(행 하나에 몰림)을 빠뜨림 |
```

## 6. 끝내기

- 정한 개수를 다 묻거나 개발자가 그만하자고 하면 끝낸다
- 요약: ○△× 개수, 약한 주제, 다음에 다시 볼 ID 목록
- `_history.md` 변경을 커밋: `[docs] 퀴즈 기록 YYYY-MM-DD` (Co-Authored-By 포함)
