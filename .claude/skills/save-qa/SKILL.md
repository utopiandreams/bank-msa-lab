# save-qa: 질답을 질문 은행에 저장

목적: 개발자가 이 프로젝트가 끝난 뒤 `/quiz-me`로 질문을 받고 답하며 복습한다. 그래서 저장하는 것은 **설명문이 아니라 질문**이고, 답은 채점 기준이 될 만큼 정확해야 한다.

## 1. 무엇을 저장할지 정한다

- 인자가 있으면 그 주제·범위. 없으면 이 대화에서 **가장 최근에 이어진 질답 묶음** (개발자가 저장하라고 한 지점까지)
- 대화 속 사실만 쓴다. 대화에서 확인하지 않은 내용을 지어내지 않는다. 라이브러리 내부 동작처럼 확인한 것은 답에 `✅ 확인`을 붙인다 (jar·소스·테스트로 확인한 경우만)
- 범위가 애매하면 한 줄로 "○○부터 ○○까지 저장하겠습니다"라고 밝히고 진행한다 (묻느라 멈추지 않는다)

## 2. 기존 은행을 읽는다

- `docs/learning/question-bank/` 의 주제 파일 목록과 `README.md`의 ID 규칙을 확인한다
- 같은 내용의 질문이 이미 있으면 새로 만들지 않고 그 질문의 답을 보강한다
- 주제 파일은 넓은 주제 단위다 (예: `concurrency.md`, `io-and-event-loop.md`, `outbox-and-events.md`, `saga.md`, `kafka.md`, `infra.md`). 맞는 파일이 없으면 만든다
- ID는 `<주제 접두사>-<세 자리 번호>`, 그 파일의 마지막 번호 다음부터 (예: `CC-013`)

## 3. 질문을 만든다

질답 하나에서 **3~6개**, 아래 유형을 섞는다. 같은 사실을 다른 각도로 묻는 것이 핵심이다.

| 유형 | 모양 | 예 |
| --- | --- | --- |
| 개념 | 면접관이 처음 던지는 질문 | "조건부 UPDATE가 동시 출금에 왜 안전한가요?" |
| 꼬리 | 앞 답을 파고드는 질문 | "그럼 락은 안 걸리나요? 격리 수준이 바뀌면요?" |
| 상황 적용 | 요구사항을 주고 선택·근거·트레이드오프를 묻는다 | "선착순 쿠폰 1,000장, 일일 한도까지 있다면 무엇으로 막겠어요?" |
| 장애 | "이 순간 X가 죽으면/늦으면?" | "Redis 락을 쥔 서버가 unlock 전에 죽으면 대기자는?" |
| 비교 | 둘 이상을 대조 | "스핀 락과 pub/sub 락의 처리량 차이는 어디서 오나요?" |
| 우리 프로젝트 | 내 코드·결정을 방어 | "왜 락 대기 상한을 1초로 했나요?" |

- 상황 적용·장애 질문을 최소 하나씩 넣는다 (개발자 요청: "어떤 상황을 주고 어떻게 적용할 것인지")
- 난이도 ★(기본) ★★(꼬리·적용) ★★★(내부 동작·여러 개념을 엮음)
- 질문은 답을 암시하지 않게 쓴다

## 4. 형식 (주제 파일에 추가)

```markdown
### CC-013 · 상황 적용 · ★★
**Q.** 선착순 쿠폰 1,000장을 발급한다. 동시에 수만 명이 누른다. 무엇으로 막고, 무엇을 포기하나요?

<details><summary>답 핵심</summary>

- 남은 수량이 행 하나에 있으면 조건부 UPDATE (`SET remain = remain - 1 WHERE id = ? AND remain > 0`), 0행이면 소진
- 대가: 행 하나에 몰리면 처리량 상한 = 1 / (UPDATE~커밋). 넘으면 수량을 여러 행으로 쪼개거나 Redis DECR + 비동기 확정
- 꼬리 대비: 사용자당 1장 제한은? → (사용자, 쿠폰) UNIQUE = 멱등과 같은 방법
- 📎 docs/learning/concurrency.md 2절, pitfalls 33
</details>

- 출처: 2026-11-22 원자적 UPDATE 질답
```

- 답은 3~6줄 불릿. 채점할 때 볼 **핵심 키워드**가 드러나게 쓴다. 장황한 설명은 📎 링크로 넘긴다
- 📎에는 저장소 안의 문서·코드·테스트 경로를 단다 (있으면 pitfalls 번호)

## 5. 설명 자료도 확인한다

- CLAUDE.md 6장 7-1-0: 질답의 설명은 주제별 `docs/learning/<주제>.md`에 있어야 한다. 없거나 빠졌으면 같이 보강한다 (질문 은행은 질문, 학습 문서는 설명)

## 6. 마무리

- `README.md`의 주제별 질문 수 표를 갱신한다
- 개발자에게 짧게 보고: 몇 개를 어느 파일에, 유형별 개수, 질문 제목 목록(답은 보여 주지 않는다 — 나중에 퀴즈로 쓸 것이라)
- 커밋: `[docs] 질문 은행: <주제> N개` (프로젝트 커밋 규칙, Co-Authored-By 포함). 다른 변경과 섞지 않는다
