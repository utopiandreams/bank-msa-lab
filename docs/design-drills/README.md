# 설계 연습 (Design Drills)

목적: 분산 흐름 설계를 **겉핥기에서 능숙함으로.** 같은 사고 도구를 여러 상황에 직접 적용하고, 장애 질문으로 두들겨 맞으며 익힌다.
시스템 설계 면접에서 실제로 나오는 형태이기도 하다.

## 하는 법 (한 문제에 30분 안팎, 코드 없음)

1. 아래 목록에서 하나 고른다 (번호 순서 추천: 쉬운 것 → 긴 시간·부분 처리)
2. `NN-<이름>.md` 파일을 만들고 **템플릿**을 채운다. 모르는 칸은 "모름"이라고 적는다 (빈칸보다 낫다)
3. Claude에게 리뷰를 요청한다 → Claude는 정답을 주기 전에 **장애 질문**을 던진다 ("2단계 성공 후 3단계 타임아웃이면?", "보상이 실패하면?", "같은 요청이 동시에 두 번 오면?")
4. 질문에 답하며 설계를 고친다. 마지막에 Claude가 실무 해법·놓친 점·면접 꼬리 질문을 정리한다
5. 막히면 [`00-example-transfer-core.md`](00-example-transfer-core.md) (이 프로젝트에서 실제로 한 설계를 템플릿으로 채운 예시)를 본다

## 템플릿

```markdown
# NN. <시나리오>

## 1. 흐름
누가 → 누구에게 → 무엇을 (홉마다 한 줄). 로컬 트랜잭션으로 묶이는 구간은 묶어서 표시

## 2. 홉 분석표
| 홉 | ① 호출 전에 커밋할 흔적 | ② 응답을 못 받으면 상태 | ③ 재시도 멱등 키 | ④ 결과 확정 수단 | ⑤ 실패 시 앞 단계 되돌리기 |
| --- | --- | --- | --- | --- | --- |

## 3. 상태 머신
상태 목록 + 전이 (끝 상태 표시, "모름" 상태가 홉마다 있는지)

## 4. 장애 시나리오
| 언제 죽나 / 무엇이 실패하나 | 그때 데이터 상태 | 누가 어떻게 고치나 (재시도 / 보상 / 조회 / 대사 / 사람) |
| --- | --- | --- |

## 5. 중복·동시성
같은 요청이 두 번(순차 재시도 / 동시) 오면? 키는 누가 만드나 (클라이언트 키 / 자연 키)

## 6. 대사 포인트
마지막 안전망: 무엇과 무엇을 맞춰 보면 어긋난 걸 찾을 수 있나

## 7. 헷갈리는 것 / 질문
```

## 문제 목록

| # | 시나리오 | 새로 연습하는 것 | 난이도 |
| --- | --- | --- | --- |
| 00 | 당행 송금 transfer → core (예시, 풀이 있음) | 홉 1개, 결과 불명, 고객 멱등 키 | ★ |
| 01 | **주문 결제:** 주문 생성 → PG 승인 → 재고 차감 → 포인트 적립 | 되돌릴 수 없는 외부(PG)가 **처음**에 낀 흐름, 뒤 단계 실패 시 보상 순서 | ★★ |
| 02 | **선착순 쿠폰 1인 1장:** 1,000장 한정, 동시 접속 수만 명 | 자연 키 + UNIQUE vs 락 vs 재고 카운터, 초과 발급 방지 | ★★ |
| 03 | **좌석 예약:** 좌석 임시 점유 → 10분 안에 결제 → 확정, 안 하면 해제 | **시간이 지나면 바뀌는 상태**(TTL), 결제는 됐는데 점유가 이미 풀렸다면? | ★★★ |
| 04 | **타행 이체** (이 프로젝트 5주 차의 예습): transfer → core 출금 → 외부 은행 송금 → 실패 시 출금 취소 | 홉 2개, 보상 트랜잭션, 보상의 실패와 멱등, 미정산 임시 계정 | ★★★ |
| 05 | **카드 결제:** 승인 → (다음 날) 매입 → (며칠 뒤) 정산, 그 사이 취소, 몇 달 뒤 차지백 | **며칠~몇 달 사는 상태**, 끝난 거래가 다시 열림 | ★★★★ |
| 06 | **주문 부분 취소·환불:** 카드 + 포인트 + 쿠폰으로 산 상품 3개 중 1개 취소 | **부분** 처리, 결제 수단별 비율 배분, 반올림 오차, 쿠폰 조건 깨짐 | ★★★★ |
| 07 | **해외 송금:** 환전 → 중계 은행 2곳 → 수취 은행, 몇 주 뒤 반송 가능 | 외부 참여자 여럿, 홉마다 다른 확정 수단, 환율이 바뀌는 사이의 결과 불명 | ★★★★★ |

> 04는 5주 차 티켓 전에 풀어 두면 그대로 ADR-0002의 초안이 된다

## 도구 상자 (설계할 때 꺼내 쓰는 것들)

- **흔적 먼저 커밋:** 원격 호출 전에 "하는 중" 상태를 커밋 → 죽어도 찾을 수 있다
- **모름 상태:** 원격 호출 경계 하나마다 "보냈는데 아직 모름"이 하나 생긴다 (ADR-0001)
- **멱등 키:** 구간마다 자기 키. 재시도와 새 요청을 구분할 수 있는 쪽이 만든다
- **상태 조회:** 모름을 확정하는 수단. 상대가 "이 키로 처리된 거 있어?"에 답할 수 있어야 한다
- **보상:** 되돌릴 수 없는 단계 뒤에서 실패하면 앞 단계를 취소하는 반대 동작. 보상도 실패할 수 있고, 멱등해야 한다
- **Outbox:** DB 커밋과 메시지 발행 사이의 틈을 없앤다 (6주 차)
- **대사:** 위 전부가 놓친 걸 잡는 마지막 그물. 실무 철학은 "완벽히 막기"가 아니라 "어긋나면 찾아서 맞춘다"
- **사람:** 수작업 조정은 실패가 아니라 설계의 일부다 (조정 전표, 승인자 분리, 감사 로그)
