# 도메인 노트: 무엇을 실제 금융처럼 만들 것인가

> 2026-11-11 개발자와 합의한 방향. 2주 차 ADR(`docs/adr/0001`)의 재료로 쓴다.

## 1. 원칙: 상품의 가짓수가 아니라 "돈이 움직이는 방식"을 실제처럼

예금, 적금, 여신을 다 만들면 도메인은 넓어지지만 새로운 분산 시스템 문제 없이 CRUD만 늘어난다. 대신 실제 금융 시스템이 돈을 다루는 방식을 재현한다.

| 구분 | 항목 | 실제 금융에서는 | 이 프로젝트의 실험 소재 |
| --- | --- | --- | --- |
| 실제처럼 | 복식부기 원장 | 모든 거래는 차변·대변 한 쌍, 합계 0 | 정합성 검증의 기준 |
| | 거래 불변 (append-only) | 수정하지 않고 반대 거래로 정정 | 보상 트랜잭션 |
| | 거래 상태 머신 | 요청 → 처리 중 → 완료/실패/**결과 불명** | 타임아웃 시 "돈이 나갔나?" |
| | 타행 이체 | 외부 결제망 연동, 실시간 처리와 사후 정산 분리 | `bank-mock` 지연·장애 |
| | 일일 대사 | 내부 원장 ↔ 외부 기록 비교 | 배치, 불일치 탐지 |
| | 감사 로그 | 누가, 언제, 무엇을 (법적 보존 의무) | Outbox/이벤트 |
| | 멱등성 | 같은 요청이 두 번 와도 한 번만 | Idempotency-Key |
| 맛보기 | 이자 (일 단위 계산 배치) | 매일 밤 전 계좌 이자 계산 | **배치와 실시간 송금의 같은 계좌 경합** |
| | 영업일, 마감 시각 | 마감 이후 거래는 다음 영업일 | 대사 기준 시각 |
| 안 함 | 적금, 여신, 카드, 환전 | | 새로운 분산 문제 없음 |

면접 문장: "상품은 입출금 계좌 하나로 줄이고, 복식부기 원장, 결과 불명 거래 처리, 일일 대사, 이자 배치와 실시간 거래의 경합처럼 실제 금융 시스템이 돈을 다루는 방식을 재현했습니다."

## 2. 잔액과 원장
- **원장이 진실(source of truth).** 잔액은 원장 거래 기록을 합산한 결과다.
- 그런데도 `account`가 잔액을 따로 들고 있는 이유: (2주 차 ADR에서 답할 것) 매번 합산하는 비용, 동시 출금 시 잔액 확인
- 둘이 안 맞으면: 누가, 언제 발견하고 어떻게 고치나 → 일일 대사 (8주 차)

## 3. 은행 간 송금은 어떻게 돈이 움직이나
**실물 돈은 움직이지 않는다. 장부의 숫자만 움직인다.**

| 등장인물 | 역할 |
| --- | --- |
| A은행, B은행 | 고객 계좌(장부) 보유 |
| 금융결제원 | 은행 간 이체 메시지 중계 (전자금융공동망) |
| 한국은행 | 은행들의 계좌 보유. 최종 정산 |

```
① [즉시] A은행: 고객 계좌 -10만
② [즉시] A은행 → 금융결제원 → B은행: 이체 메시지
③ [즉시] B은행: 수취인 계좌 +10만 (수취인은 몇 초 만에 받음)
④ [나중에, 보통 다음 영업일] 차액결제: 하루치 A↔B 송금을 상쇄하고 차액만 한국은행 장부에서 이동
```

- B은행은 돈을 받기 전에 먼저 지급한다 → 결제 불이행 위험 → 은행들은 담보를 맡긴다.
- ②에서 응답이 없으면 **결과 불명** → 상태 조회로 확인 (8주 차)
- 원장에서는 ①~④ 사이의 돈을 **미정산 임시 계정(가계정)**으로 처리한다:
  ```
  ① 차변: 고객 예금 -10만 / 대변: 타행이체 미정산 +10만
  ④ 차변: 타행이체 미정산 -10만 / 대변: 한국은행 예치금 -10만
  ```
  대사로 "미정산 잔액이 정산 후 0이 되는지" 확인한다.
- 한계: 결제망의 실제 전문 형식, 정산 시각 등 세부 규칙은 흉내만 낸다. 구조(실시간 처리와 사후 정산의 분리)를 이해하고 반영하는 것이 목표다.

## 4. 결정: 금융결제원은 따로 만들지 않는다
- `bank-mock` 하나가 "외부 결제망 전체(금융결제원 + 타행)"를 대표하는 블랙박스다.
- 흉내 낼 행동: ① 지연·실패·응답 없는 타임아웃 ② 상태 조회 API ③ 하루 거래 내역 제공 (대사용)
- 차액결제는 흉내 내지 않는다 (미정산 계정 + 대사로 충분).

| 시기 | 범위 |
| --- | --- |
| 2~5주 차 | **당행 이체만.** 외부 연동 없음 |
| 8주 차 | 타행 이체: `bank-mock` 연동, 결과 불명 처리, 미정산 계정, 대사 (+ 이자 배치 검토) |
| 15주 차 | `bank-mock` 지연으로 장애 전파 실험 |

- 2주 차 ADR에는 "송금은 당행/타행 두 종류이고, 타행은 8주 차에 추가한다"고만 적는다.
