# Tailscale은 어떻게 포트를 열지 않고 집에 들어가나

> 2026-11-23 개발자 질문 ("이거 어떤 메커니즘인지 궁금하다"). 밖에서 클러스터에 붙으려고 노트북 `bank-cp3`를 서브넷 라우터로 만든 날.
> 사실 확인: 맥북·bank-cp3의 `tailscale status`, `netstat -rn`, `tailscale ping` 출력으로 확인한 것은 ✅ 표시. 리눅스 네트워크 딥다이브(백로그)와 이어진다.

## 1. 큰 그림: 제어는 중앙, 데이터는 직접

```
              [조정 서버 login.tailscale.com]  ← 공개키·주소·경로 목록만 주고받음 (데이터는 안 지나감)
               ▲ 공개키, 내 바깥 주소          ▲
               │                               │
[맥북 100.80.129.117] ══ WireGuard (UDP) ══ [bank-cp3 100.100.83.88] ── enp2s0 ──▶ 172.30.1.0/24
                      직접 연결 실패 시 DERP 릴레이 (암호문만 중계)
```

- 💡 **제어 평면(control plane):** 기기마다 WireGuard 키 쌍을 만들고 **비밀키는 기기 밖으로 안 나간다.** 조정 서버에는 공개키, Tailscale 주소(`100.x`), 내가 보이는 바깥 주소 후보, 광고한 경로만 올린다. 서버는 이걸 모아 기기마다 "피어 목록(netmap)"을 내려준다
- 💡 **데이터 평면(data plane):** 실제 패킷은 기기끼리 WireGuard로 **종단 간 암호화**해 보낸다. 조정 서버가 털려도 트래픽은 못 읽는다 (대신 가짜 피어를 끼워 넣을 수는 있다 → 그래서 관리 콘솔 계정 보안이 곧 네트워크 보안)
- 💡 k8s에 빗대면: 조정 서버 = API 서버(원하는 상태 배포), 각 기기의 `tailscaled` = kubelet(받아서 로컬에 적용)

## 2. 왜 포트를 안 열어도 되나: NAT 홀 펀칭

- 💡 공유기 NAT는 "안에서 먼저 나간 연결의 응답"만 들여보낸다. 그래서 바깥에서 먼저 들어오는 연결은 막힌다 (포트 포워딩이 필요한 이유)
- 💡 Tailscale은 **양쪽이 동시에 서로에게 UDP를 쏜다.** 각자의 NAT 입장에선 "내가 먼저 보낸 상대의 응답"으로 보여 통과시킨다 = 홀 펀칭. 상대의 바깥 주소는 STUN(내가 밖에서 어떤 IP:포트로 보이나 묻기)으로 알아내 조정 서버로 교환한다
- 💡 휴대폰 망 같은 **대칭형 NAT**(목적지마다 바깥 포트가 바뀜)는 펀칭이 잘 안 된다 → **DERP 릴레이**로 우회. 릴레이는 암호문만 넘긴다. 느려질 뿐 끊기진 않는다
- ✅ 오늘 확인: `tailscale ping bank-cp3` → `via 112.182.110.207:41641 in 8ms` = **집 공인 IP로 직접 연결** (릴레이 아님). 맥북이 집 안에 있어서 공유기가 자기 공인 IP로 되돌려 보낸 것(헤어핀 NAT). status의 `Relay tok`는 "필요하면 쓸 DERP 지역 = 도쿄"라는 뜻

## 3. 서브넷 라우터: 100.x가 아닌 172.30.1.x로 어떻게 가나

```
맥북: kubectl → 172.30.1.230:6443
  1. 라우팅 테이블: 172.30.1/24 → utun6 (Tailscale 가상 인터페이스)
  2. tailscaled가 패킷을 WireGuard로 감싸 bank-cp3로
bank-cp3:
  3. 풀어 보니 목적지가 자기가 아님 → ip_forward=1 이라 커널이 enp2s0으로 넘김
  4. 출발지를 자기(172.30.1.202)로 바꿈 (SNAT, Linux 기본값 --snat-subnet-routes=true)
  5. 응답은 bank-cp3로 돌아옴 → conntrack이 되돌려 다시 WireGuard로 맥북에
```

- 💡 **ip_forward를 켠 이유:** 리눅스는 기본으로 "남의 패킷"을 넘기지 않는다 (라우터가 아니라 호스트라서). 설치 때 `/etc/sysctl.d/99-tailscale.conf`로 켰다
- 💡 **SNAT를 하는 이유:** 집 안 장비(k8s API 서버)는 `100.x`가 어디 있는지 모른다. 출발지를 bank-cp3로 바꿔야 응답이 bank-cp3로 돌아온다. 대가: 집 안 장비 로그에는 모든 원격 접속이 `172.30.1.202`로 찍힌다 (X-Forwarded-For 고객 IP 유실과 같은 모양)
- 💡 **경로 광고 + 관리자 승인 2단계:** 기기가 "이 대역을 맡겠다"고 광고해도, 관리 콘솔에서 승인해야 다른 기기에 배포된다. 기기 하나가 털려도 마음대로 대역을 가로채지 못하게
- ✅ 오늘 확인: 승인 전 bank-cp3의 `PrimaryRoutes`는 비어 있었고, 승인 뒤 `['172.30.1.0/24']`로 바뀌었다

## 4. 집 안에서는 왜 Tailscale을 안 타나

- ✅ 맥북 라우팅 테이블에 `172.30.1/24`가 **두 줄** 있다: `en0`(와이파이, 직접 붙은 대역)과 `utun6`(Tailscale). `route get 172.30.1.202` → `en0`
- 💡 macOS Tailscale은 지금 붙은 LAN과 겹치는 경로를 덮어쓰지 않는다 → 집에서는 와이파이로 바로, 밖에서는 `en0` 줄이 사라져 자동으로 `utun6`. 설정을 바꿀 필요가 없다
- ⚠️ 이 성질 때문에 생기는 함정: 밖의 네트워크도 `172.30.1.0/24`이면 (KT 공유기 기본 대역이라 흔하다) 그쪽 LAN이 이겨서 집에 못 들어간다 → pitfalls 35

## 5. 왜 Wake-on-LAN은 Tailscale을 못 넘나

- 💡 매직 패킷은 **브로드캐스트**(같은 L2 세그먼트 전체에 뿌림)다. Tailscale은 **L3 터널**(IP 패킷을 특정 상대에게 전달)이라 브로드캐스트를 집 LAN에 퍼뜨리지 않는다. 게다가 꺼진 장비는 IP도 없다 → MAC 주소로 같은 LAN에서 외칠 수밖에 없다
- 💡 해결: 집 LAN 안에 **항상 켜진 장비**가 대신 외친다. `cluster-up.sh`의 `wake()`가 bank-cp3에 SSH로 들어가 보낸다 (2026-11-23부터 집 안·밖 같은 경로)

## 🎤 면접 꼬리 질문

- "VPN 서버 없이 어떻게 P2P로 붙나요? 둘 다 NAT 뒤인데?" → 홀 펀칭(STUN + 동시 송신), 안 되면 릴레이
- "조정 서버가 해킹당하면 트래픽이 노출되나요?" → 비밀키가 기기에만 있어 내용은 못 본다. 다만 피어 목록을 조작할 수 있어 관리 계정·키 만료·ACL이 중요
- "서브넷 라우터 뒤의 서버는 왜 응답을 돌려보낼 수 있나요?" → SNAT. 끄면 집 안 장비에 `100.64.0.0/10` 경로를 따로 넣어야 한다
- "Tailscale과 Cloudflare Tunnel은 뭐가 다른가요?" → Tailscale은 **내 기기끼리의 사설망**(접속하는 쪽도 클라이언트 필요), Tunnel은 **불특정 다수에게 공개**(브라우저만 있으면 됨, 앞단에 Access로 인증). 이 프로젝트는 본인 접속 = Tailscale, 면접관 시연 = Tunnel(백로그)
- "포트 포워딩과 비교하면?" → 집 공인 IP와 열린 포트가 인터넷 스캐너에 노출되지 않는다. 들어오는 연결이 하나도 없다
